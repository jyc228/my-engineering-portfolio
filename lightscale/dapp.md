# DApp 서비스 개발

## 프로젝트 개요

- 기간: 2024.10 - 2025.12 (약 4개월)
- 인원: 4명
- 핵심 기술: kotlin, spring boot, postgresql, web3j
- 주요 역할: 백엔드 리드

당시 회사는 어려운 상황이었습니다.

- 오래 투자했던 핵심 기술이 경쟁 프로젝트보다 성능이 낮다는 평가를 받았고, 핵심 개발자가 퇴사한 상태였습니다.
- 런웨이가 약 6개월 남은 상황이라 신규 서비스를 빠르게 런칭해야 했습니다.
- 백엔드 리드 개발자도 퇴사가 예정되어 있었습니다. 저는 블록체인 코어에서 백엔드로 포지션을 옮기면서 백엔드 리드 역할을 맡겠다고 했고, 설계부터 코드 리뷰, 팀원 지원까지 맡게 되었습니다.

## 주요 업무

### 개발 프로세스 정리

일정이 짧고 팀 구성(주니어 2명, 현업 개발에서 떨어져 있던 CTO)상 리뷰 여력이 부족해서 아래와 같이 진행했습니다.

- **통합테스트 작성 필수화** : 모든 코드를 꼼꼼히 리뷰할 시간이 없어서, 통합테스트를 쉽게 작성할 수 있는 기반을 만들고 작성을 필수로 했습니다.
  시나리오 단위로 로직을 먼저 검증하니 리뷰 시간이 줄었고, QA 기간 백엔드 버그는 5개 이하였습니다.
- **도메인별 패키지 구조** : 4명이 한 프로젝트에서 충돌 없이 작업하고 각자 맡은 도메인이 분명하도록 도메인 단위로 패키지를 나눴습니다.
- **공통 코드 라이브러리화**: 반복되는 설정과 보일러플레이트를 라이브러리로 분리해서, 팀원들이 비즈니스 로직 구현에 집중할 수 있게 했습니다.
- **코드 리뷰** : 주니어 2명의 코드는 원래라면 전부 꼼꼼히 리뷰해야 했지만 시간이 부족했습니다.
  통합테스트 시나리오를 먼저 검토하고 문제가 없으면 승인한 뒤, 코드 품질은 이후에 따로 챙겼습니다.
- **에러 알림** : 별도 모니터링 도구를 도입할 여유가 없어서 에러 리포트를 슬랙으로 보내되,
  같은 에러는 스레드로 묶어 메시지가 넘치지 않게 했습니다.

이때 라이브러리를 만들었던 경험은 이후 공통 라이브러리 작업에 도움이 되었습니다. [platform.md](../bunjang/platform.md) 를 참고해 주세요.

### 타 파트 협업 및 외부 연동

- **연동 규격 정의**: `Frontend`, `Smart Contract` 파트와 연동 규격을 정하고, 컨트랙트 호출 부분은 백엔드에서 감싸서 제공했습니다.
- **외부 서비스 연동**: 리워드 지급을 위해 `Web3j`(블록체인)와 `외부 포인트 API`를 연동했습니다.

### 팀 멘토링

회사가 어려운 상황이었지만 팀원들이 흔들리지 않도록, 코드 리뷰와 업무 가이드를 통해 계속 대화하면서 같이 진행했습니다.

## 성과

QA 기간 동안 백엔드 버그는 5개 이하였고, 서비스는 일정 내에 런칭했습니다.

이 프로젝트를 마지막으로 퇴사했습니다.
